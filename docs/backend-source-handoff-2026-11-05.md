## 前端可以依赖的接口

FastAPI 基址默认 `http://127.0.0.1:8000/api/v1`，前端通过受控同源 `/api/bluepulse/*` 代理读取。已实现的匿名 GET：`/health/live`、`/health/ready`、`/sources`、`/taxonomy`、`/articles`、`/articles/{uuid}`、`/articles/availability`、`/home/recently-collected`、`/home/featured`、`/site/timeline`、`/entities`。具体字段、过滤器和错误形状见 [后端 README](../backend/README.md)及运行实例的 `/openapi.json`。

`/articles` 默认 `period=30d`，旧稿需 `period=all`；只返回当前可公开、非重复、非撤回且相关的稿件。`/site/timeline` 是近 30 日公开材料的时间线，归组和热点字段当前为空。`/home/featured` 只读取已生成快照，不会在 GET 时采集或调用模型；当前没有正式精选数据。`/entities` 返回真实空目录；`entity` 筛选暂返回空。详情只在来源独立允许全文时提供正文，否则可展示摘要和原站 URL。正式 `backend/data/bluepulse.db` 截至本次检查为 **0 个 source、0 篇 material**，所以空列表不能解释为前端故障。

[前后端接口总册](../dock.md)中的 DOCK-006 同新闻组、DOCK-007 热点、DOCK-008 日报、DOCK-009 reader/Markdown/海报/OG 等是前端预留或专项验收结果；对应的真实 FastAPI 生产能力目前未完成。前端应保留空态和原站跳转，不把 mock、合成许可样本或模型判相关当作已公开新闻。

## 继续推进的具体项目

1. **真实公开资格**：逐来源确认摘录/全文许可与转载归属，在已有门禁下选择允许对外展示的来源；对一篇正文达标的真实稿做正式库从采集到分类再到公开 API 的受控验收。当前不能凭模型结果自动打开许可。
2. **模型质量**：以小批人工金标核对相关性、摘要事实、五轴分数，校准各来源精选门槛；否则双评分完成也只会是 `uncalibrated`。正文超过 4,200 字符的评分输入截取边界要在评测中覆盖。
3. **自动运行**：把现有 `source_worker` 接入系统任务与目标库，并补跨进程预算/并发互斥和故障告警。可立刻重复限量验证，但单日成功不等于持续稳定；零候选与失败要分开记录。
4. **前端尚需的数据生产**：若要首页精选/同新闻组/热点/日报真正有内容，还需 Fact/Story 归组、精选快照生成、热点和日报生成及公开读取接口。当前不应为这些路径构造成功响应。

本阶段按已定产品口径推进：不要求人工审核才可公开，不把旧稿一概剔除，也不把取得附件作为所有正文稿的硬条件；保留 robots、访问限制和来源许可门禁。
