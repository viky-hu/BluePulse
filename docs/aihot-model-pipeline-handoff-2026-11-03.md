日期：2026-11-03。**本次交付是源码研究、实施交接和文档口径更新，不是后端实现或业务验收。** 用户确认沿用原分工：后端由队友在其分支实施，用户决定并执行合并；前端及相关文档直接在 `main` 维护。

## 1. 已确定目标与当前基线

目标是将真实信源材料通过可恢复、可追溯的模型链路，接通 Pulse 已有的精选、热点和日报界面。自动筛选发布，管理员可以纠正和撤回；全部动态宽收，精选宁缺毋滥。模型按步骤可配置，初期共用一个兼容接口模型。本期包括日报；周月刊维持现状，不新增独立主题菜单、普通账号、项目档案、站外推送或模型榜。

本轮核对的 Pulse 基线为 `main@8738045`，开工时工作区干净，本地可见迁移到 `0007`。队友的信源提交尚未合并，**下表只描述该基线，不能用于否定或验收队友未合并的工作**。信源合并后先逐项更新基线，再安排迁移编号和集成。

## 3. 实施工作包与依赖

工作包按 B→C→D→E→F 的依赖顺序推进，管理权限和审计随每个管理写操作一起交付；对应旧阶段图的 B／C／D／E／F／G。**内部表名和 Python 拆分由后端结合合并后的实现制定，以下是行为与验收要求，不是要求照单建表或固定任务框架。** 全部工作包及真实联调完成后，才可宣布本轮整体交付完成。

### B：信源合并复核、材料版本与领域配置

- [ ] 用户合并信源工作后，记录合并提交、最新迁移、来源配置／调度、正文与时间状态、现有测试；列出已覆盖和仍缺的项。不得重写已发布迁移或清空旧数据。
- [ ] 各采集入口先持久化材料与待处理状态，再交给分析；包括当前在适配器内部处理模型的采购来源。重复发现不增 revision，实质变更及可信日期补全按原机制失效旧分析；旧结果可追溯但不覆盖新输入。
- [ ] 分开保存发表、首次发现、来源更新、修订和公开确认时间。沿用未来超过1小时不可信、迟发现超过48小时／未知日期／显式回灌的处理；历史且陈旧或未知日期的材料不制造事件热度。
- [ ] 来源分级、发布者／所属机构、参与方式和全文许可分别配置。`trust_level` 不自动转换成 T1／T1_5／T2，官方标签不自动证明效果或主体代表资格；许可未知保持关闭。
- [ ] 分类复核必须区分两套现状：主线旧后端／历史金标使用 `policing` 等宽分类，前端目标为 `product/practice/paper/law/embodied/public-opinion/low-altitude`（DOCK-004）。信源合并后据实对齐；不把两套七类视为相同，不静默改旧深链或机械映射旧标签。历史重分类需有输入／提示词版本和人工覆盖保护。
- [ ] 在领域配置明确栏目顺序、未分类处置、评论性内容及受控实体／标签；不能直接把未知类别塞入最后的“低空”栏目。独立主题菜单不在本期范围。

交付：升级／备份／恢复说明、旧文章兼容策略、来源身份／许可配置、版本与日期测试。现有 UUID、原始 URL、原文和人工标注不丢失；不编造旧文章的历史版本、授权或模型信息。

### C：付费回执、按能力配置和持久任务

- [ ] 在大规模双评分／归组前实现统一调用出口。保留现有 `BLUEPULSE_LLM_API_BASE/API_KEY/MODEL` 的迁移说明；能力配置最初指向同一模型。解析优先级沿用 AIHOT 的管理员设置→环境覆盖→代码默认，任务保存实际生效配置；切换影响后续新任务，不悄悄重算历史。
- [ ] 调用身份包含任务、材料 revision、实际输入、模型／服务配置、提示词内容哈希及参数；评分1和评分2身份不同，不能复用同一响应充当两次独立评分。显式重评使用新身份，普通恢复继续原身份。
- [ ] 发送前持久化请求身份与 attempt；收到响应先独立提交原始响应、usage、request ID、耗时和费用来源，再解析并提交业务。保存失败或发送后断线不可推断“未计费”；已保存结果在业务失败后复用。
- [ ] 区分 received／completed、在途、提供方拒绝、格式失败、预算等待和 unknown。原实现将10分钟陈旧 pending 转 unknown；unknown 超过30分钟允许自动放行一次并审计，再次 unknown 必须人工注明计费核对及理由。计数与放行由事务保护，不能并发重复处理。
- [ ] 分钟／小时／日预算按实际 attempt 计算，包含重试；这是请求次数保护，不是严格金额上限。实际费用与 token 估算分列，没有价格或usage时显示未知。原实现“删除预算行即无限制”不作为 Pulse 未配置时的默认启用方式。
- [ ] 新模型调用总开关默认关闭，预算未配置时不得启用自动付费。采集、补分析、翻译、评测共用出口，避免保留旁路；历史 `selection_eval` 也要迁移。日志和请求摘要不保存密钥。
- [ ] 队列／租约覆盖重分析与翻译，领取、续租、提交检查所有权与输入版本。实时材料优先于回灌，补扫找回写库后漏排的任务；预算等待不作为文章无关，unknown不作为普通失败立即重发。
- [ ] 停机不领取新的付费工作，在途调用先保存响应再关库；服务停止期限大于最长调用和保存余量。原195秒停止期限是180秒单次调用加余量的参考，不在修改调用超时后仍机械保留。

交付：可控假提供方、持久任务／回执迁移、预算与配置示例、状态／错误／恢复接口和离线故障测试。不能承诺网络未知时绝不重复计费；通知投递不沿用模型unknown的一次自动放行政策。

### D：预筛、双评分、事实抽取与写作

- [ ] 固定流程为“材料补全→预筛→双评分与结构化并行→写作→候选”。结构化不等待评分，写作等待结构化；失败时等待在途结构化响应保存，不能遗失付费结果。
- [ ] 预筛 BLOCK停止、PASS／UNKNOWN继续；缺材料时不能以未出现某词判无关。继续分析不等于允许公开，缺少可用材料仍有独立发布门禁。核对所有来源级关键词规则，保留发现成本控制，去除与领域预筛冲突的最终否决旁路。
- [ ] 沿用五轴、类型权重和噪声规则结构，警务化重要性／噪声实例；评分输入不带来源分级、门槛或旧分数。两分之和≥两倍门槛才够分，显示floor平均值；必须两次完整，拒答或单次成功不算通过。没有已校准门槛不自动候选入选。
- [ ] 分类、标签、主体及 `single/composite/unknown` 来自结构化。事实包含主体、动作、对象、明确发生日期、原文证据与限定条件；证据及条件摘录必须在实际输入原文中连续可查，不能拿标题／译文补证据或把综合稿变成一次发生。
- [ ] 够分或平均分严格高于 understandFloor 的资料采用理解式标题、答案先行摘要及理由，其余用短摘要。AIHOT的50与60/65/76只作对照，Pulse使用已记录的校准配置；所有源材料和其中指令均为不可信数据。
- [ ] 只描述实际看见的正文／摘要，记录截断范围；不按URL或模型记忆补事实。空正文／纯链接不生成替代正文。摘要写事实，理由写关注价值；招标、预告、试点、部署和效果评估不得混写。

交付：独立提示词资源、严格步骤输出校验、提示词／输入／结果版本、共享生产步骤的评测入口。[标注指南v2](selection-annotation-guide.md) 统一人工判断口径；旧20条数据和人工决定原样保留，不伪造五轴分项。

### E：事件关系、确认门禁、发布与翻译

- [ ] 保留 Article（一份材料）、Fact（同一次发生）、Story（事件及直接进展）；关系为 SAME_OCCURRENCE／SAME_STORY／UNRELATED／ROUNDUP，证据角色为 primary／report／mention。采购、招标、试点、验收是不同动作；同一厂商或地区相似项目不能因此合并。
- [ ] 使用原14天召回及字符bigram后备路径；独立测试召回漏检和关系误判。归组、必要复核和综述共用回执；格式／置信度不足进入失败／待处理，人工归属与拆合不被自动重跑覆盖。
- [ ] 保留原精选表达式语义：`selectionCandidate && groupingComplete && (manualSelected === true || selectionAddsValue !== false)`。null不同于false；人工selected可覆盖增量否决，但不跳过候选和归组完成。明确scope不足且无fact的分支由归组写addsValue=false，不误写成评分直接确认事件。
- [ ] 等待归组的候选只在符合资格的全部动态可读；不因等待超时自动精选。超过10分钟进入运营诊断，不通过虚假成功或补足六条消除等待。
- [ ] 发布服务集中读取当前分析与人工覆盖，区分列表、详情、精选、证据和导出资格。保留Pulse现有公开范围；是否采用AIHOT更宽的“未收录也可有详情”需另有明确契约，不在本次迁移顺带放宽。
- [ ] 代表排序沿用T1、经身份核验能代表事件主体的机构／个人、许可全文、分数、时间、稳定ID；暂停来源与撤回文章分别处理。站内全文与再分发许可独立，旧正文字段／收藏快照／报告不能绕过当前权限。
- [ ] 全文翻译按已精选、公开且可显示全文的资格后台执行。复用按块保护媒体／代码／链接、批次回执、revision绑定和完整性；中文原文不重复翻译。部分译文可保留，但不得称为完整，旧译文不可代表新修订。对接DOCK-009现有可选reader与后续接口，不在此扩展独立事件页面。

交付：事件与发布迁移、纠错／撤回审计、阅读组及当前后续读取、旧精选迁移说明。网页可有多篇同事实报道；六槽封面、时间线、同新闻组和未来机器出口代表席位不是同一概念，本期不增加RSS／MCP／同步ledger接口。

### F：真实热点与规则日报

本节将热点与日报放在一起说明联调顺序；与旧阶段图对应时，热点仍属E，日报属F，不另造一套阶段编号。

- [ ] 热点沿用48小时窗口、24小时半衰期；同参与方窗口内只计一次，至少2参与方且至少1 editorial参与方才进入排名候选。以可信来源时间记录信号，不能用抓取时间把旧文变热。
- [ ] 当前来源角色、owner／媒体矩阵与有效事件证据决定参与方；暂停采集与撤回证据不同。维护来源成功时钟与起监时间，6小时趋势只比较可比群体；覆盖不足可为unknown，小时缺测为null。
- [ ] 每5分钟排名、每小时快照；保存complete状态并在补采后修复。主榜与内嵌条同一排名；读取重新核对代表、撤回、归组和释放，不重新编号rank。sourceCount／participantCount／reportCount／有限名单不能互推；曲线25个含两端小时槽，不插值补造缺测。
- [ ] 日报独立刊期，默认北京时间08:00，窗口前日08:00至当日08:00，左闭右开；确认或释放跨截止归下一期。六槽快照和articles按日截取不能冒充日报。
- [ ] 沿用前7自然日记忆（含快讯／related并追溯当前归组）、同Story一条、最高报道面Fact的权威代表、综合稿折叠；日内独立参与方参与importance，不直接用热榜rank／衰减热度排日报。
- [ ] 官方原帖且3个以上独立参与方的有效事实可依原条件补选日报，但不因此入精选或推送。旧事件新进展遵循当事方非commentary新动作或4来源门槛；全为跟进时仍可有正文。
- [ ] 每源最多2条，最多12正文／10快讯；第一条头条，其后最多3条看点。平静刊要求窗口已有判断但无重大内容，上游无判断为任务失败待补刊。每半小时补缺刊，已出刊不自动重写，显式订正保存理由与旧版。
