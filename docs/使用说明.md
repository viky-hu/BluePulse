# BluePulse 使用说明（Windows 本地版）

本文适用于当前 `repo` 目录中的 BluePulse。它说明怎样启动、阅读、采集、标注和检查系统。当前版本以本机使用为主；网页端**没有“立即采集”按钮**，也没有可用的管理员后台。下文中“推送”指平台内部的采集、精选和展示，不包含邮件、手机通知或订阅。

## 1. 最快开始：打开并阅读已有文章

1. 双击项目根目录的 `启动BluePulse.bat`。它会检查后端虚拟环境和前端依赖，并分别启动 API（`127.0.0.1:8000`）与网页（`127.0.0.1:3000`）；准备好后打开浏览器。首次启动可能需要等待片刻。启动窗口关闭后，两个服务窗口仍须保持运行。
2. 打开 <http://127.0.0.1:3000/>。入场动画结束后，点击或滚动进入主页面。白纸上的精选来自真实接口；如果近 7 天没有合格精选，会显示空态说明，不是启动失败。若近期资讯也为空，主页面会出现“最近收录”：仅列已审核公开文章，按本站首次收录时间排列，同时明确标出原文发布日期；它不是今日新闻或本期精选。点击卡片可查看详情，“查看全部”进入全部时间的文章库。
3. 打开[文章库](http://127.0.0.1:3000/articles)。默认看近 30 天；想检查之前采集的文章，切换到“全部时间”。可以按关键词、主题、地区、厂商／模型、来源类型、具体来源和排序筛选。
4. 点击文章进入站内详情。先看中文摘要和正文状态，再核对可用的中文译文、原文与“前往原始来源”。`summary_only` 表示仅有摘要，不能当作全文；正文或译文缺失时以原站内容为准。

可以直接打开一篇已入库样本，检查完整阅读路径：<http://127.0.0.1:3000/articles/4be281c8-e78b-46a3-88f3-735fcc69f591>。如果日后该样本被删除或数据库被重建，请从文章库重新选择一篇。

只有显式添加 `?mock=1` 才使用演示数据；正常地址不混入假新闻。首页精选不足六条时不凑满六条。

### 停止服务

双击 BAT 启动后，分别在“BluePulse API - 8000”和“BluePulse Web - 3000”窗口按 `Ctrl+C` 或关闭窗口。关闭启动 BAT 自己的窗口**不会**停止这两个服务。手动从终端启动时，也在对应终端按 `Ctrl+C`。标注页和每日调度是独立进程，要在各自窗口另行停止。

## 2. 首次安装或换电脑

在 PowerShell 进入项目根目录（下面路径是当前电脑的示例，换位置时改为实际路径）：

```powershell
cd 'D:\311实验室实用项目\警务科技情报\repo'
pnpm install --frozen-lockfile
cd backend
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m bluepulse_backend.worker sync-config
```

先确认 `node`、`pnpm` 和 `py` 在 PowerShell 中可用。后端项目要求 Python **3.12 或更新版本**；实际使用哪个兼容版本由本机环境决定。以后更新了后端依赖，再在 `backend` 目录执行 `pip install -e .`；更新了数据库迁移，再执行 `alembic upgrade head`；修改了 `backend/config/sources.json`、主题或实体清单，再执行 `sync-config`。`sync-config` 同步配置，**不抓新闻**。

默认数据库是 `backend/data/bluepulse-dev.db`（SQLite）。这份文件和密钥文件不要提交到 Git。切换 PostgreSQL 需在迁移、API 与 worker 所在的每个终端设置相同的 `BLUEPULSE_DATABASE_URL`；当前还没有完成 PostgreSQL 实机验收，不建议把本地试用直接视为生产部署。

### 模型配置

模型地址、密钥和模型 ID 默认从 `repo` **上一级**的 `.env` 读取，字段名分别是 `base_url`、`key`、`llm_id`。也可以使用 `BLUEPULSE_LLM_API_BASE`、`BLUEPULSE_LLM_API_KEY`、`BLUEPULSE_LLM_MODEL` 环境变量，或以 `BLUEPULSE_ENV_FILE` 指定配置文件。不要将密钥复制进文档、日志或截图。模型地址需为 HTTPS。

无有效模型配置时，只有标题、摘要或正文的原始材料可能被保留为待处理，不能期待自动生成中文摘要并公开展示。正式采集和历史重处理可能调用付费模型；下面的只读检查不会调用模型。

## 3. 日常采集与处理

以下命令都从 `repo/backend` 目录运行。若尚未进入该目录：

```powershell
cd 'D:\311实验室实用项目\警务科技情报\repo\backend'
```

| 想做什么          | 命令                                                                                                                   | 是否写库／调用模型        |
| ------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------- |
| 只采集一个来源       | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker ingest-once --source govuk-policing-tech`                    | 写库；新候选可能调用模型     |
| 采集所有已启用来源     | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker ingest-once`                                                 | 写库；可能耗时并调用模型     |
| 查看各来源最近采集状态   | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker source-status`                                              | 只读，不调用模型         |
| 预览待补跑的失败来源     | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker retry-failed`                                               | 只读，不调用模型         |
| 执行失败来源补跑       | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker retry-failed --apply`                                       | 写库；新候选可能调用模型     |
| 预览中断的采集运行     | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker recover-interrupted`                                         | 只读，不调用模型         |
| 恢复一项中断运行       | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker recover-interrupted --apply`                                 | 写库；新候选可能调用模型     |
| 查看待处理积压       | `.\.venv\Scripts\python.exe -m scripts.pending_audit`                                                                | 只读，不调用模型         |
| 补分析有正文／摘要的旧文  | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker reprocess-pending --source openalex-policing-tech --limit 5` | 写库，调用模型          |
| 仅补人工确认相关的旧文   | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker reprocess-pending --editorial-only --limit 5`                | 写库，调用模型          |
| 补译已处理的短篇英文全文  | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker translate-pending --source govuk-policing-tech --limit 3`    | 写库，调用模型          |
| 回填厂商／模型实体关联   | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker backfill-entities`                                           | 写库，不调用模型         |
| 每天 06:00 自动采集 | `.\.venv\Scripts\python.exe -m bluepulse_backend.worker schedule`                                                    | 常驻进程；届时写库并可能调用模型 |

`schedule` 使用 Asia/Shanghai 时区。它不是 Windows 服务：电脑和该终端必须保持运行。可以同时启动手动采集或补跑，但所有采集入口共用一把数据库租约锁；撞车的一方返回 `busy`，不会并发写入。同一天的定时运行还使用固定幂等键，重复启动不会重复执行当天任务。单来源失败不会让其他来源立即停止，但应检查失败记录。

`source-status` 显示每个已启用来源最近一次尝试的状态、起止时间、发现／入库／重复数量、失败类型与原因，以及最近成功时间。`retry-failed` 默认只预览最近一次状态为 `failed` 的来源；确认后加 `--apply` 才逐个补跑。要限定一个来源可加 `--source 来源slug`；部分成功的来源默认不补跑，需要明确加 `--include-partial`。状态为 `succeeded`、`skipped`、`running` 或从未运行的来源不会进入默认补跑名单。补跑可能访问外站、写库和调用付费模型；不会绕过外站访问挑战或 GDELT 限流冷却。

首次使用新版采集命令前，在 `backend` 目录运行 `.\.venv\Scripts\python.exe -m alembic upgrade head`。锁租约为 120 秒，运行中每 20 秒续租；进程突然退出后需等租约到期，下一次采集会把原运行标为 `interrupted`。用 `recover-interrupted` 查看可恢复项，再加 `--apply` 一次恢复一项（重跑原来源范围，并非从某条文章内部断点继续）。文章 URL 去重可避免重复入库，但崩溃前尚未提交的外站请求或模型调用仍可能重做。手动重复提交可指定 `ingest-once --source 来源slug --idempotency-key 自定义键`；同一键与同一来源范围只执行一次，结果带 `idempotent_replay`。不要把同一键复用于不同来源。普通手动采集不指定键时，每次都是新运行。锁只覆盖采集相关入口，不覆盖 `reprocess-pending`、`translate-pending` 等维护命令。

### 怎样看采集结果

`ingest-once` 返回 `run_id`、`status`、`sources`、`source_failures`、`discovered`、`inserted`、`duplicates`、`irrelevant`、`deferred`、`model_failures`、`model_calls` 等计数。重点看：

- `status: succeeded`：本次运行完成；不代表每条新闻都相关，也不保证首页有精选。
- `status: partial`：至少一个来源或详情／模型步骤部分失败，检查 `failures`、`source_partials`、`detail_parse_failed`。
- `inserted`：写入数据库的原始条数，**包含后来判无关或仍待处理的记录**，不等于网页新增条数。
- `duplicates`：URL 已存在；重复运行出现这个数字通常正常。
- `deferred`：超过本轮分析上限而暂缓的新候选；后续运行可继续处理。
- `model_failures`：模型分析失败，原始材料仍保留；修复配置／网络后可对有摘要或正文的记录运行 `reprocess-pending`。

文章库只显示已处理且未被人工判为无关的文章。只拿到标题的 GDELT 条目即使入库，也不会冒充可阅读新闻。模型可能把 RSS 中的普通案件或活动判为无关；这是筛选结果，不是采集故障。旧文章按**原始发布时间**排序，不会因为今天重新采集就变成“今日新闻”。

## 5. 人工标注与复核（可选）

这套本地标注页用于检查“相关／不相关”“是否精选”和主题建议，**不是公开网站的管理后台**。当前工作区已有 20 条试标文件；换电脑或清空 `backend/data/` 后需先恢复该文件，不能凭空打开原有标注。

在 `repo/backend` 运行：

```powershell
.\.venv\Scripts\python.exe -m scripts.selection_review
```

打开 <http://127.0.0.1:8765/>。每页 8 条；下拉选项修改后即时保存，理由停止输入约 0.7 秒后保存，逐条核对后点击“确认本条”才计入已复核。不要同时启动两个标注服务，也不要在页面打开时直接编辑 `data/selection-pilot-20.jsonl`。关闭服务用 `Ctrl+C`。更详细的判定口径见[选稿标注指南](selection-annotation-guide.md)。

标完后验证文件；若要应用到文章数据库，务必先备份数据库并先预览：

```powershell
.\.venv\Scripts\python.exe -m scripts.selection_dataset validate --input data/selection-pilot-20.jsonl
.\.venv\Scripts\python.exe -m scripts.apply_selection_gold
# 核对预览影响范围后，才运行下一行；它会修改数据库
.\.venv\Scripts\python.exe -m scripts.apply_selection_gold --apply
```

人工决定与模型建议分开保存；确认无关的旧文将不再公开，确认相关但尚未完成模型处理的文章不会凭标注直接公开。只读的模型回放命令是 `python -m scripts.selection_eval --limit 15`（会调用模型并可能产生费用，但不改数据库）；留出集用 `--split holdout --limit 5`。

## 6. 常见问题

| 现象                                       | 先检查什么                                                                                                                        |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 双击 BAT 一闪而过或报缺文件                         | 在 PowerShell 中运行 BAT 查看错误；检查 `backend/.venv/Scripts/python.exe` 和 `node_modules/.bin/next.cmd`，必要时按第 2 节安装。不要把 BAT 移到别处单独运行。 |
| 网页提示连不上情报服务                              | 确认两个服务窗口仍开着；分别访问 `127.0.0.1:3000` 与 `127.0.0.1:8000/api/v1/health/ready`；检查 3000、8000 端口是否被别的程序占用。                           |
| 首页没有精选，文章库却有内容                           | 精选另有相关性、价值与近 7 天时间窗口；切换文章库到“全部时间”，不要把空精选当作采集失败。                                                                              |
| 采集 `inserted > 0`，网页没有新增                 | 看 `irrelevant`、`processing_status`、`parse_status` 和时间筛选；标题级或模型失败记录不会公开。                                                      |
| `ModuleNotFoundError: bluepulse_backend` | 从 `repo/backend` 目录使用 `.venv/Scripts/python.exe -m scripts.脚本名`，不要在任意目录直接双击 `.py`。                                           |
| 中国政府采购网 TLS 握手失败                         | 先用普通浏览器检查该站和本机网络；本机曾出现 VPN 路径不通。也可能是站点或证书链问题，不能仅凭 TLS 错误断定反爬；不绕过证书校验。                                                        |
| Police1 返回 WAF／验证页                       | 记为来源访问受限，不使用伪装、代理或验证码绕过；可先测试其他来源。                                                                                            |
| 模型失败或一直待处理                               | 检查服务端模型配置、模型额度和网络；用 `pending_audit` 区分有摘要与只有标题的记录，后者不能靠模型补写全文。不要在聊天或日志中泄露密钥。                                                 |
| 模型 `ReadTimeout` 或“未返回有效 JSON”           | 先确认模型列表和一次极短推理是否都能返回；列表正常不代表该模型通道正常。本机曾发现 Qwen 推理超时，而同账户 DeepSeek 正常。选择 DeepSeek 时分类会用 JSON 模式和较高输出预算，避免推理先耗尽输出额度。不要靠无限延长超时或关闭 TLS 校验处理。 |

## 7. 当前边界与数据安全

当前版本可试用“配置来源 → 手动或定时采集 → 内容处理与去重 → SQLite 存储 → 首页／文章库／详情／原站追溯”的基本链路，但不等于已完成全部 Stage1 验收。文章库的关键词检索在 SQLite 使用 FTS5 索引，覆盖中英文标题、正文与中文摘要；两字以内的查询使用普通模糊匹配。详情页明确区分正文不足、尚未翻译、翻译失败与原文过长；旧文章历史失败原因不可追溯时只显示保守状态。本轮不做图片展示。带权限的管理后台、网页内采集按钮以及 PostgreSQL 全文索引和实机验证仍待完善。采集任务锁已通过本地 SQLite 并发测试，尚需在目标 Windows 常驻运行和 PostgreSQL 环境验证。修改源码或生产数据前先备份本地数据库并运行 `alembic upgrade head`；不要把 `.env`、`backend/data/`、人工标注原始文件或个人信息提交到公开仓库。

架构和验收范围见[Stage1 完成门槛与 Stage2 路线](stage2-plan.md)；开发细节和最新来源限制见[后端 README](../backend/README.md)。
