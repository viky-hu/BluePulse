# Blue Pulse 系统整体构建大纲

> 本文是 Blue Pulse 的产品与系统路线总纲，供前端、后端和后续研究/运营协作使用。它记录目标能力与分期，不表示尚未实施的页面或后端服务已经存在。Stage1 的可交付后端边界见 [`stage1-backend-plan.md`](./stage1-backend-plan.md)。

## 1. 系统定位

Blue Pulse 是面向研究人员、兼顾公众阅读的国内外警务科技情报系统。系统持续采集与警务科技相关的公开资讯，也关注可能影响警务科技发展的重要上游进展，尤其是中国和美国的人工智能、大模型及相关厂商动态。它把分散的公开信息整理为可阅读、可检索、可追溯的中文资讯，而不是把未经核实的模型输出包装成事实。

首版聚焦中国与美国，前台地区维度以“国内 / 国外”呈现，不把国家做成复杂的一级导航。主题负责回答“这条资讯讲什么”，厂商/模型、来源类型、地区和时间是可组合的浏览维度。原始标题、原文内容（可获得时）、来源与原网址应保留，机器生成的中文标题、摘要和译文不能取代原始材料。

### 产品原则

- 先保证信息可读、可查、可回到原始来源；再逐步形成事件、项目和趋势研判能力。
- 每篇文章必须标注来源与原文链接。模型生成内容应能与原文对照，不能补写原文没有的数字、组织或结论。
- 自动采集、整理并发布；管理员可以在发布后查看、软删除或恢复低质量文章。首版不是“先人工审核再发布”的工作流。
- 桌面和移动端均是正式使用场景。现有桌面设计测量基准为 34×19 视口比例；响应式实现使用视口比例和移动端独立约束，不把厘米作为 CSS 单位。
- 首版只面向匿名公众阅读与部署人员维护的管理员；暂不建设普通用户账号、个人订阅和个性化推荐。

## 2. 现有前端基础与入口体验

当前前端已实现 Next.js 初始封面及 GSAP/SVG 动效，并在封面中以 p0–p5 六张 mock 白纸承载新闻标题和日期。首页路由目前仍渲染初始页；新闻主页、搜索、分类和新闻详情尚未接入。这些 mock 数据是视觉占位，不是已运行的新闻后端。

封面后续接入真实数据时，p0 展示优先级最高的精选文章，p1–p5 展示其他精选文章。六张白纸均应可点击并进入同一文章详情视图。优先级和窗口规则详见 Stage1 后端计划。

## 3. 前端信息架构

### Stage1 页面与栏目

| 页面 / 栏目 | 主要作用 | 关键内容与交互 |
| --- | --- | --- |
| 初始封面 | 保留现有品牌与动效入口 | 动效完成后进入近期简报；支持减少动态效果的静态路径 |
| 近期简报首页 | 快速了解近期值得关注的资讯 | p0–p5 精选、近24小时/近7天/近30天时间挡位、主题入口、近期资讯流 |
| 资讯浏览 / 搜索 | 连续阅读和查找文章 | 关键词、时间、主题、国内/国外、厂商/模型、来源类型组合筛选；排序与分页 |
| 主题分类 | 按主要内容领域阅读 | 七个首版一级主题；可增补二级主题和标签 |
| 厂商 / 模型目录 | 浏览指定组织或模型相关报道 | 实体目录数据驱动，不在前端写死某几家厂商；组织和模型可互相链接 |
| 新闻详情 | 查看单篇新闻的完整可用材料 | 中文标题、原始标题、摘要、译文/原文、媒体、来源与原网址；缺失内容明确回退 |
| 来源说明 | 了解资讯出处及覆盖范围 | 来源名称、类型、覆盖主题、最近采集状态（公开状态范围由后端接口决定） |
| 管理入口 | 维护公开资讯与检查采集运行 | 管理员登录后查看已发布文章、软删除/恢复、查看采集运行并手动补跑 |

### 页面与后端能力映射

| 前端模块 | 前端责任 | 后端责任 / 数据 |
| --- | --- | --- |
| 封面精选 p0–p5 | 显示日期、短标题、加载/空状态；点击进入文章详情 | 生成精选 edition 与槽位、输出文章卡片摘要；应用24小时优先/7天补足规则 |
| 近期首页 | 选择时间挡位、进入主题或筛选后的资讯流 | 返回精选、近期文章及主题/地区/实体汇总 |
| 资讯流和搜索 | 显示结果、分页、组合筛选、空结果状态 | 文章全文索引/关键词查询，按时间、主题、地区、来源和实体过滤 |
| 主题分类 | 展示固定一级主题和服务端提供的子类/标签 | 维护 taxonomy ID/slug，文章分类与关联 |
| 厂商 / 模型目录 | 浏览实体说明及其关联文章 | 规范组织/模型实体、别名、地区和实体—文章关系 |
| 新闻详情 | 呈现译文/原文切换、媒体、来源、原站链接和解析回退提示 | 解析内容和媒体元信息、翻译状态、来源引用；未获取的字段明确返回不可用 |
| 来源说明 | 展示来源范围和公开来源信息 | 来源元数据和公开状态；内部密钥、抓取细节和安全错误仅管理端可见 |
| 管理入口 | 管理文章可见性、查看运行和触发补跑 | 管理员会话、软删除审计、运行任务/来源结果与受控手动重跑 |

厂商/模型目录的数据示例可以包括 OpenAI、Anthropic、xAI、DeepSeek、智谱、阿里云/通义、百度等，但它们只是首批实体候选，不是前端固定栏目或封闭枚举。随着来源覆盖变化，可由后端实体数据扩充和规范别名。

首版一级主题：

1. 警务应用：情报研判、执法办案、指挥调度、交通管理、治安与应急等作为子类或标签。
2. AI 与大模型：模型发布、智能体、多模态、推理、行业解决方案等。
3. 公共安全技术装备：视频分析、生物识别、无人机/机器人、物联网与通信等。
4. 网络与数据安全：网络安全、隐私保护、数据治理等。
5. 政策与标准：法规政策、行业规范、技术标准与治理动态。
6. 采购与项目：招标采购、中标、建设、试点、部署和验收等公开信息。
7. 研究成果：公开论文、研究报告、测试评估及学术成果。

国内/国外、厂商/模型、来源类型和时间是跨主题维度。分类表应由服务端数据驱动；未识别到的组织或模型可作为待整理实体保存，不应因实体字典尚无记录而丢弃文章。

### 后续前端栏目

- **事件与项目**：把多篇报道归并到同一事件或项目，呈现项目生命周期与时间线。
- **Radar / 趋势**：按主题、技术、机构和地区呈现一段时间内的变化，并链接回构成趋势的来源文章。
- **证据与核验**：显示关键陈述由谁提出、有哪些来源支持、是否存在独立证据或来源冲突；不简单给出真假标签。
- **知识关系浏览**：探索机构、技术、项目、模型之间的关系。
- **关注清单与通知**：用户订阅主题/组织/关键词，选择即时提醒或摘要；需要普通用户身份体系后再建设。
- **日报 / 周报 / 专题报告**：以可追溯文章为依据生成情报摘要和专题观察。
- **来源管理后台**：新增、编辑、停用来源和调整采集策略；Stage1 暂由配置文件维护。

## 4. 后端能力总框架

将“确定性数据服务”与“模型辅助理解”分开，避免把系统设计成彼此调用的 Agent 集群。模型只负责定义清楚、可审查的文本任务；抓取、安全限制、去重、调度、存储、发布、权限和审计由普通程序控制。

```text
来源配置
  → 调度与运行记录
  → 采集适配器（RSS / API / HTML 等）
  → 正文与媒体解析、时间与链接规范化
  → 去重与文章存储
  → 分类 / 实体标注 / 翻译 / 摘要 / 标题浓缩 / 重要性评估
  → 质量标记与自动发布
  → 精选、检索、详情及管理 API
  → 桌面与移动端前台
```

| 能力域 | 责任 | 阶段 |
| --- | --- | --- |
| 来源目录与采集适配 | 维护来源元数据、抓取公开资讯、限制访问频率并记录来源健康 | Stage1 配置文件；后续来源后台 |
| 调度与运行管理 | 计划任务、补跑、并发控制、失败记录和重试 | Stage1 |
| 解析与规范化 | 提取文章正文/媒体、规范 URL 和日期、识别语言 | Stage1，先覆盖可稳定获取的网页/RSS/API |
| 文章库与检索 API | 保存原始与处理后的文章，支撑时间/主题/实体/关键词检索 | Stage1 |
| 内容智能处理 | 分类、地区/实体识别、中文短标题、摘要与翻译、重要性排序 | Stage1；由可替换云模型适配器调用 |
| 发布与精选 | 质量状态、近期精选快照、自动发布和管理员事后处理 | Stage1 |
| 事件 / 项目归并 | 多文章归并为事件和项目，维护阶段与时间线 | 后续阶段 |
| 核验与证据 | 提取关键陈述、关联来源和证据、记录冲突与核验状态 | 后续阶段 |
| 分析与关系 | 趋势、Radar、知识关系与周期性报告 | 后续阶段 |
| 用户服务与外部推送 | 登录用户、关注清单、个性化通知及邮件/即时通讯等渠道 | 后续阶段 |
| 运营、安全与可观测性 | 管理员认证、审计、日志、健康检查、备份与告警 | 基础能力随 Stage1 建设并逐步增强 |

数据演进主线：

```text
Source → Article → Event → Project
                    ↘ Entity / Technology
                    ↘ Claim → Evidence
Article / Event → Trend / Report / Alert
```

Stage1 只实现 Source、Article、实体/分类标签、媒体元信息、精选快照、采集运行、管理员与审计等直接支撑阅读闭环的结构。事件、项目、Claim、Evidence、Trend、Report 和 Alert 是后续概念，不应为追求抽象而提前构建空壳服务。

## 5. 分阶段路线

### Stage1：资讯闭环（本次后端交付范围）

- 中国与美国的中英公开来源，警务科技主线与重要上游 AI 动态。
- 每日定时采集和管理员手动补跑；正文解析、去重、中文处理、分类、自动发布。
- p0–p5 近期精选；资讯浏览、时间/主题/地区/实体筛选、搜索和详情接口。
- 匿名阅读；部署人员创建管理员；管理员查看文章、软删除/恢复和检查采集运行。
- 数据/API 契约、模型适配边界、集成测试、部署配置说明。

### Stage2：事件与证据

- 跨来源事件匹配、项目档案与阶段时间线。
- Claim/Evidence 结构、来源交叉验证、来源冲突和可信度说明。
- 可控的来源管理界面与更丰富的解析器。

### Stage3：情报分析

- 趋势、Radar、国家/机构/技术比较、知识关系浏览。
- 日报、周报和专题报告，结果可追溯到文章和证据。

### Stage4：个性化和规模化

- 普通用户、关注清单、偏好和个性化推送渠道。
- 扩展地区、语言、来源规模及可靠性/成本治理；按实际容量拆分数据库、对象存储或队列。

## 6. 当前非目标

- Stage1 不实现跨文章事件/项目归并、知识图谱、事实验证 Agent、趋势预测或自动报告。
- Stage1 不实现公开注册、个人收藏/订阅、个性化推荐、外部即时推送。
- 不以无限制爬取、绕过登录/验证码或抓取非公开评论来补全内容；来源必须是经配置的公开来源。
- 不默认复制或托管来源站点的图片/视频二进制文件；首版优先保存可用链接与解析元信息。
