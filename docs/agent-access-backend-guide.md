# BluePulse Agent 接入页：后端设计指南

把 Agent 接入做成公开内容的只读出口。首版提供 Markdown 接入说明和 JSON 查询，共用现有网页文章列表的公开查询及权限规则。接口请求读取已发布的数据，不触发抓取、模型调用或发布任务。MCP 暂缓。页面如何展示见[前端设计指南](agent-access-frontend-guide.md)。

## 先定能力和接口

首版以“最新资讯”和“关键词搜索”为最小闭环。以下是 2026-11-06 的后端契约；公开 URL 由服务端固定配置 `BLUEPULSE_SITE_ORIGIN` 生成，缺失或无效时三个 Agent 路由返回 503，不从请求 `Host` 推导。

| 接口 | 首版行为 |
| --- | --- |
| `GET /api/v1/agent` | `text/markdown` 接入说明：能力、参数、默认值、示例、数据范围和出处用法。 |
| `GET /api/v1/agent/latest` | JSON，按原发布时间倒序；`window=7d`、`limit=10` 为默认，时间窗可选 `24h/7d/30d`。 |
| `GET /api/v1/agent/search` | JSON，用 `q` 查询**公开标题与摘要**；`window=all`、`limit=10` 为默认，时间窗可选 `24h/7d/30d/all`。 |
| 现有 JSON API | 供程序取数，沿用现有字段、分页和版本。接入页提供链接即可。 |

`limit` 为 1–30，`q` 去除首尾空格后为 2–200 字符。`24h` 只包含具有精确原发布时间的稿件；仅有日期的稿件可进入 `7d/30d`，响应标注 `date_precision=date`，不虚构时分秒。搜索默认全库以保留旧稿。只有现有公开数据能支撑时才增加精选切换、热点、事件详情或报告。

## 查询与输出

```text
网页 / REST JSON / Agent Markdown
                ↓
        统一的公开查询服务
                ↓
       公开性、撤回和转载许可
                ↓
        已发布的内容与出处
```

- **先过滤再分页。** 列表与 Agent 查询先用 SQL 缩小到公开、未撤回、非重复、来源允许摘录且正文级的候选，再逐篇按当前 `visible()` 规则复核，合格行才计入页数。`q` 只查公开标题和摘要；站内全文许可不扩展为 Agent 正文再分发许可。收录时间和原文发布时间分开表达。
- **规则要能解释。** 默认按时间排序并用稳定 ID 处理同一时间的排序。当前搜索直接查全部符合时间窗的公开稿，不暗中改用精选或扩大范围；响应写明实际查询窗口。
- **保留证据。** JSON 每条提供公开 ID、标题、摘要、来源、原发布时间或日期、日期精度、首次收录时间、站内链接和原文链接，不输出正文、内部评分或模型回执。外层为 `schema_version=1`、`query`（查询种类、实际时间窗、条数、搜索词、排序口径）和 `items`。Markdown 说明列明时间窗和资料范围。
- **把资讯当外部数据。** 在 Markdown 和工具说明中标记标题、摘要等外部内容为不可信数据，提醒 Agent 不执行其中的指令。由后端控制字段、链接协议和输出边界；这类提示不能替代权限过滤。
- **区分空结果和故障。** 查无匹配返回 200 和空 `items`；非法参数返回 422，站点地址未配置或数据库不可用返回 503。统一错误结构不暴露内部日志或数据库信息。

## 部署与验收

正式部署需要把 `/api/v1/agent*` 路由接到后端，配置 `BLUEPULSE_SITE_ORIGIN` 为公开站点的固定地址，并限制匿名查询速率与超时。当前后端统一返回 `Cache-Control: no-store`，撤回和许可变化会在下一次读取生效。当前前端 `/agent` 仍是栏目入口壳；部署后的接入页只能展示实际可访问的地址。

验收至少覆盖以下场景：

1. 用普通 HTTP 客户端经真实部署入口读取 Markdown 指南，按示例请求两个 JSON 接口；确认链接使用固定站点地址。
2. 在同一数据和参数下对比 Agent JSON 与现有公开文章列表的结果范围、顺序和链接。确认未公开内容、撤回内容、仅在正文中出现的搜索词和未经许可的正文不出现在 Agent 出口。
3. 检查空结果、非法参数、超限、站点地址缺失、查询超时和服务故障。确认 Agent 可以分辨“没有找到”和“目前查不了”。
4. 确认查询请求不会触发采集、写作、发布或其他写操作。部署完成后再把地址和能力清单交给接入页。

AIHOT 的 `apps/api/src/routes/agent.ts` 与 `packages/backend/src/publication/agent.ts` 可作职责划分参考；当前本机未找到 `D:/AIHOT` 快照，未在本轮直接复核这些原文件。本站实现以 `backend/bluepulse_backend/{public_reads,agent_access,api}.py` 和本指南为准。MCP 协议层留待后续单独设计与验收。
