本次白话说明验收：21 项样本／评测兼容检查通过；五类填写场景、确认记录用语、保存及离线交回文件的浏览器检查通过；实际 120 条文件的电脑、手机、减少动态效果检查无脚本错误或横向溢出。全部 20 个选择项均有直接可见的解释。lint 和隔离副本生产构建通过，新闻及 96／24 划分指纹未变。截图位于 `test-results/selection-review-plain-language/`。

## 先理解系统在做什么

```text
每个信源到期抓列表 → 入口校验与去重 → 原始材料／修订入库 → 补正文
  → 模型预筛 → 两次独立评分＋事实与分类结构化 → 中文标题摘要
  → 公开资格 → 归组与精选确认 → 热点与规则日报 → 前端读取已存结果
```

Pulse 与 AIHOT 都先保留材料，再保存分析结果及发布状态。数据库中的材料不等于公开稿，相关也不等于精选。重复采集可以没有新增，已处理材料不因网页刷新而再次调用模型。前端目前按加载、导航、刷新读取，没有向已打开页面持续推送新闻的 WebSocket／SSE。

原始源码依据是 AIHOT 的 `content/materials.ts`、`sources/collect.ts`、`editorial/analyze.ts`、`providers/receipts.ts`、`operations/recover.ts` 和 `docs/selection.md`。复用的是材料先存、独立评分、回执先存、未知结果单独处理和开发集／留出集校准的机制；Pulse 继续使用 Python/FastAPI、SQLAlchemy/SQLite 和现有 Next.js 前端。实质源码复用遵守 [MIT 声明](../THIRD_PARTY_NOTICES.md)。D:/AIHOT 是下载快照，不代表本轮验证过其线上站点。

## 启动检查：服务正常与内容链路正常分开报告

```powershell
# 在 D:/pulse 运行；均不初始化数据库、不创建凭据、不启动或重启服务
.\Pulse.bat --check-config
.\Pulse.bat --check-health
.\Pulse.bat --probe-model
```

- `--check-config` 检查 worker 配置语法，不访问供应商，不证明凭据有效。
- `--check-health` 只读检查本机服务、worker 实际锁及配置、来源最新状态、入库、模型回执、失败任务、滚动请求预算和来源许可。只对本机服务发 GET，不向供应商发生成请求。
- `--probe-model` 在上述检查之外访问供应商 `/models`。列出模型也不代表生成质量、账户额度或每种处理步骤已经验证。
- 普通启动完成原有服务检查后，同样输出内容链路审计。发生降级时提示原因并保留运行服务，不通过重新初始化或清库消除问题。
- 健康检查退出码：`0` 表示服务就绪且本次未发现降级；`1` 表示服务缺失、检查不可用或存在降级。历史失败任务也会使检查返回 `1`，应结合原因判断，不能只看退出码停止服务。

机器可读检查：

```powershell
cd D:/pulse/backend
.\.venv\Scripts\python.exe -m bluepulse_backend.runtime_health --json
```

报告区分请求配置与运行中 worker 的实际配置。无新增、全是重复候选不是采集失败。HTTP 200、已收到回执和业务处理成功分别表达；供应商内容拦截保留为 `sensitive_words_detected`，不盲目重试。

本机审查时有 263 篇材料、514 次来源采集、221 篇接口公开统计、1,265 次模型尝试。回执包含 1,258 次 HTTP 200、3 次内容拦截，以及 4 次历史超时尝试；1,261 个逻辑回执均已有响应。251 篇是历史材料，5 篇日期未知，7 篇标为新稿且未达到相应门槛；精选和日报为 0，不能为填空而降低门禁。本轮新增只读检查再次确认三项服务就绪及模型列出；后续来源轮询数字会继续变化。

进程监督、异常自动重启、开机恢复、定期备份与恢复演练、实际域名和 HTTPS、反向代理配置仍属于目标部署验收，BAT 成功不代表这些已经部署。本机全文、媒体和翻译资格按实际来源许可报告，不为“全开启”擅自放宽许可。

## 交给组员：只发一个 HTML 即可

本机交付文件在 `backend/data/selection-review-20261109/Pulse选稿标注.html`，该目录被 Git 忽略，文件不作为公共网站页面部署。可以把这个 HTML 复制、重命名后发给组员；无需 Python、服务器、账号或其他附件。

组员步骤：

1. 双击 HTML，用较新的 Edge 或 Chrome 打开，填写自己的姓名。
2. 阅读中文参考及原文，依次回答是否与警务科技有关、是否值得重点推荐、主要讲什么、报道具体说到哪一步，再写一句原因。每个选项旁有解释，不要求自行调查。
3. 点击“确认本条”。信息不够就如实选择判断不了，不靠猜测补事实。
4. 点击 **“导出已标注 HTML”**，下载包含结果的新文件，把下载的文件发回负责人。直接发最初收到的旧文件，不包含浏览器里的新输入。
5. 也可导出 JSON 备份；负责人在同一标注包中导入多人的 HTML 或 JSON，查看并裁决分歧，再导出汇总后的 HTML。

浏览器自动保存只负责这台电脑、这个浏览器的进度。它不能静默改写原 HTML；文件被移动、浏览器数据被清除或换电脑后，不能依赖原缓存。**导出的 HTML 自带完整结果**，在新电脑断网打开也能恢复。JSON 仍可用于备份和后续评测。

建议按编号分工，例如三人分别负责 P001–P040、P041–P080、P081–P120；额外安排 10%–20% 的重叠复核。不要共用同一个标注人姓名。每个人的确认是不可变记录；改判时追加版本，旧记录仍留存。不同人的判断（包括理由）不一致会显示分歧，不按多数票或最后写入静默生成答案。负责人须选定采纳记录并填写理由；之后有效确认变化，旧裁决自动失效。

## 这批 120 条是什么

从本机真实材料中按来源、语言和原文材料类型均衡抽样，包含 14 个来源、30 条中文及 90 条英文。正文不足 300 个非空白字符的材料不进首批，明确重复标题／正文去重；没有为了凑数生成新闻。材料类型启发式分布为政策 31、研究 28、实践／产品／新闻 53、采购 8，不等于人工确认分类。

固定 96 条开发集、24 条留出集。划分仅在负责人持有的 `manifest.private.json` 中，标注页面不显示模型分数、建议分类、推荐理由或是否属于留出集。每条绑定原材料 ID、revision、content_hash，另校验冻结原文与输入指纹。修改原文或划分不能冒充原来那版样本。

原文完整保留；超过生产分析的 12,000 字符输入时，页面明确标记截断并允许展开全文。中文是独立辅助翻译，不复用现有模型推荐摘要。翻译可能有误，判断以原文为准。本轮供应商未成功翻译的少数材料由 Codex 另作辅助翻译，隔离回执保留原始失败，不伪造供应商成功。

这批材料还没有人工金标准；不能声称已经完成警务质量校准。旧记录中的 20 条只有 3 条精选正例，来自旧流程，本机没有那份旧标注文件，也不能从代码确认具体标注人。现有 120 条补的是 AIHOT 建议的真实样本实践；上游模型发布、机器人、无人机及高价值正例覆盖须由负责人确认，不足再补真实材料。当前留出为文章级划分，尚未完成跨报道同事件泄漏审计，不能据此夸大独立泛化能力。

## 负责人收到结果后做什么

人工判断不是重新训练模型，也不会自动变成每次 API 请求中的范本。它是用来检验本站规则和门槛的参考答案。日常仍由流水线自动处理，负责人抽查和纠错。保留用户选择的 60／65／76；精选太少先查供稿、漏采、历史稿占比、分类和漏选，再决定改标准还是降门槛。

先在 HTML 内导入并消解开发集全部分歧，然后用汇总后的 HTML（或 JSON）评测：

```powershell
cd D:/pulse/backend
.\.venv\Scripts\python.exe -m bluepulse_backend.selection_evaluation --packet-dir data/selection-review-20261109 --reviews data/组员汇总结果.html --output-dir data/selection-eval-development-v1 --split development --allow-paid-model --max-model-calls 360
```

该命令会真正调用模型。没有足够确认或仍有分歧时，在读取凭据、建评测库或联网前拒绝执行。只使用生产预筛与两次评分，不运行写作、结构化、归组或发布；结果是“材料精选候选”的评测，不代表分类、公开资格、摘要事实性或事件归组都通过。

先看开发集错例修改规则，定稿后才显式开启留出集：

```powershell
.\.venv\Scripts\python.exe -m bluepulse_backend.selection_evaluation --packet-dir data/selection-review-20261109 --reviews data/组员汇总结果.html --output-dir data/selection-eval-holdout-v1 --split holdout --confirm-holdout --allow-paid-model --max-model-calls 90
```

留出集不做门槛扫描，不用来反复调规则。报告区分失败、未知、人工不确定和未评分，零分母指标为 `null`。开发集按来源、语言、人工分类报告误推和漏选，并提供 40–90 的门槛扫描，不自动修改生产阈值。每次真实尝试计入隔离库预算，回执先于结果保存；已成功响应可复用，未知结果不自动重发。本轮没有人工标注，未运行上述真实付费评测。

如只想导出已确认金标准 JSONL：

```powershell
.\.venv\Scripts\python.exe -m bluepulse_backend.selection_packet gold --packet-dir data/selection-review-20261109 --reviews data/组员汇总结果.html --output data/selection-gold-development-v1.jsonl --split development
```

开发／留出分别导出；未确认或有冲突不写文件，已有输出拒绝覆盖。原始生产数据库、来源许可和人工覆盖不会因此改变。
