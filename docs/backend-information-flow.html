01 / LIFECYCLE

从原站到读者

点选节点，查看做了什么、保存了什么。

先扫列表，记下候选与覆盖范围

常驻 worker 调度 15 个内置信源，例如中国政府采购网、江苏公安、GOV.UK、NIST、Europol 和新加坡 Police Life。适配器读取 RSS、网页分页、站点地图或原站接口。

采集遵守 robots、主机限速和 Retry-After，失败退避。停机后重扫可变列表首页；原站截断或拒绝读取时保留覆盖缺口。

留下：候选链接、发现记录、来源运行记录、列表覆盖证据和待补正文任务。

worker.py · 采集恢复审计

同一篇文章有稳定身份，每次内容变化都有版本

独立队列获取详情、正文、署名和原站发布时间。规范化 URL 识别同一条目，内容哈希判断是否修订，并通过规范标题等规则处理重复材料。

首次收录、采集和原站发布时间分开记录；只给日期就保留日期精度。正文欠缺的稿件保留待补，历史回补保留原站日期。

留下：Material 当前稿、MaterialRevision 历次内容，以及正文状态和原站出处。

pipeline.py · material_identity.py

先判断要不要读，再提取事实、评分和写中文导读

模型先做范围预筛；对继续处理的稿件提取事实、分类、标签和机构，独立做两次五轴评分，并产出中文标题与导读。文案校验核对日期、数字和行动阶段，例如不能把「招标」写成「已部署」。

后台在调用前登记，返回后先存回执，再应用结果；按修订和输入版本复用结果。超时若结果未知，保留记录待处置。

留下：当前研判修订、分数、模型回执和任务状态。人工覆盖优先于对应的模型字段。

editorial.py · receipts.py

可公开由证据和许可决定，精选另有门槛

普通公开要求：相关、摘要有效、原站链接有效、已抓取的正文至少 300 个非空白字符、来源处于编辑模式且允许摘录，并且无重复、撤回或尚未到公开时间等限制。

五轴双评分达到来源配置的门槛，只代表可能成为精选候选；普通公开不要求达到该分数。站内全文、源站媒体、站外全文再分发各有独立许可。

分流：可公开稿进入阅读池；缺证据、权限不足或退稿保留内部状态。来源许可变化可用现有研判结果重算。

publication.py

稿件记录报道，Fact 折叠同一事实，Story 串起后续进展

常驻链路会用标题和事实线索（可选向量）召回候选，再用模型判断、必要时复核。不同报道可归入同一 Fact，同一事件的不同 Fact 可归入一个 Story。

精选从当前可公开、已归组的新鲜候选中选代表稿，首页最多六席。事件证据另算热点；日报则按刊期组织正文和快讯。

留下：Fact 成员、Story 关系及证据、精选快照、热点快照和日报版本。

grouping.py · fact_grouping.py

公开时再检查；内容变了就重新走必要步骤

FastAPI 给网页和 Agent 提供读取出口，并按当前资格和出口专属许可决定给摘要、原文、译文、图片或仅原站链接。

原文修订可使旧派生内容失效并重新排队；撤稿或关闭许可会影响后续读取。已经公开的旧刊保留版本记录，引用仍须通过当前资格检查。

去向：普通阅读、编辑产品和机器接口；管理端可撤回、订正、重跑并查审计。

api.py · reading.py

02 / FOLLOW A SIGNAL

跟踪一条采购公告

教学示例，不是数据库里的实际稿件。

某市公安采购执法音视频管理系统公开阅读池
  1. 采购列表发现链接，正文任务入队。
  2. 获取正文，保留来源日期和材料修订。
  3. 抽取采购事实、校验中文导读，通过公开规则。
  4. 进入全部动态；再分别评估精选、热点和日报。

日期分两条线：绝大多数读者看到的是可核实的原站日期；日常日报归期看首次收录，历史重编才按核实的原站日期归期。

03 / DESTINATIONS

信息最后到了哪里？

以下接口路径均省略共同前缀 /api/v1。

A / FEED

全部动态与文章阅读

可公开稿进入列表、搜索和详情。全文另查许可；符合条件的外文精选稿可在后台翻译，译文绑定原文修订。

/articles · /articles/{id}
B / CURATION

首页精选与阅读组

首页最多六个席位，同一 Fact 只推一个代表；时间线和同组报道使用可见材料。推荐理由只在符合条件的代表稿显示。

/home/featured · /site/timeline · /site/groups/{fact_id}/reports
C / HEAT

热点榜与事件追踪

热点按 48 小时内独立参与方聚合，24 小时衰减半衰期；至少两个独立参与方且有编辑类信号才上榜。一篇公告可作证据，不保证有榜位。

/site/hot · /site/stories/{public_id}
D / EDITION

日报与历史档案

北京时间 08:00 划刊。日常按首次收录时间；历史模式按核实的原站日期或时间，仅有日期的材料归入次日刊。可公开的待处理稿完成后可补入原刊并留版本。

/site/reports/daily · /site/reports/daily/{key}
E / MACHINE

Agent、Markdown 与分享

Agent 提供可检索的公开条目、摘要和阅读链接。Markdown、分享图和媒体各检查可见性及适用许可。

/agent/latest · /agent/search · /articles/{id}/markdown
F / INTERNAL

运营后台与未公开材料

管理员查看采集与模型记录，调整来源许可及门槛，订正内容与归组，撤回或重新排队。读者反馈也在后台处理；收藏、已读等浏览状态留在浏览器。

/admin/* · /site/feedback

04 / IMPLEMENTATION

后端如何分工

Python worker：后台写入

列表扫描、补正文、AI 研判、归组、翻译与刊期走持久任务队列。任务领取有租约和心跳；模型调用有预算、回执和未知结果处理。

FastAPI：对外读取与后台入口

Next.js 通过站内代理访问 API。公开阅读匿名；管理写入依靠管理员会话、CSRF 防护和审计记录。

SQLite：保存证据与当前状态

SQLAlchemy 管对象，Alembic 管迁移；默认文件库用 WAL 支持读写并行。原始材料及修订、后台任务与回执、派生刊期和快照分别存储。

模型接口：按步骤转换材料

采集适配器向原站取数据；开启模型任务后，worker 按能力把相应的材料片段或证据发送到配置的模型提供方，将回执和处理结果写回本地。
