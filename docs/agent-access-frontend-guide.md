# BluePulse Agent 接入页：前端设计指南

接入页的任务是让用户知道能查什么、把什么地址填到哪里，以及怎样确认已经接通。用户仍在自己的 Agent 客户端提问；页面本身是一份接入指南，不需要内置聊天框、模型或新闻查询表单。接口约定见[后端设计指南](agent-access-backend-guide.md)。

## 页面结构

| 区域 | 应提供的信息 |
| --- | --- |
| 页首 | 一句话说明用途，例如“在你的 Agent 里查本站最新资讯和主题报道”。说明数据范围、是否只读、是否需要身份凭证。 |
| 接入方式 | 首版展示 HTTP 入口，区分给 Agent 读的 Markdown 指南和给程序读的 JSON API。MCP 与 RSS 暂不展示。 |
| 接入步骤 | 每种方式依次展示适用场景、可复制地址、配置方法和首次验证。用户不需要先读协议文档。 |
| 能力清单 | 每项能力写清“什么时候用”，并给一句可直接提问的例子。只列已部署的能力。 |
| 文档与排错 | 链接到实际发布的机器说明、API 规范；列出连接不上、查无结果和请求受限时各自怎么处理。 |

首屏优先放接入地址和复制按钮。桌面可把资源链接放在侧栏；手机把资源放到配置步骤后，保持地址可完整查看，代码块可局部横向滚动。

## 让用户完成一次真实查询

1. **Markdown：** 提供 `/api/v1/agent` 的绝对地址，给一条可复制的指令：“先读取这份接入说明，再按其中的搜索接口查询关于某个主题的公开报道，并附出处。”注明客户端需要能访问该站点。
2. **JSON：** 展示 `GET /api/v1/agent/latest?window=7d&limit=10` 与 `GET /api/v1/agent/search?q=警务技术&window=all&limit=10` 的可运行示例、参数说明及实际存在的 API 规范链接。让开发者清楚知道 Markdown 地址不会返回 JSON。

路由、版本和工具名应来自站点配置或已发布的接口契约。用部署配置生成示例地址，避免把开发地址、容器主机名或模板占位符复制给用户。页面可在后端暂时不可用时继续展示说明；若展示状态，应注明探测了什么。普通健康检查只能说明服务可响应，不能证明客户端能发现工具或查到新闻。

## 交互与验收

- 如果用标签页，允许通过 URL 直达指定方式，刷新和前进后退后仍能恢复；支持键盘切换，并让当前标签与面板语义对应。
- 复制按钮应给出可感知的成功或失败反馈。剪贴板不可用时保留可选中的地址和代码。状态用文字表达，避免只靠颜色。
- 至少检查桌面、窄屏、键盘操作和减少动态效果设置。逐项检查公开链接、配置示例和复制内容；用一个目标客户端从页面步骤走完读取说明和查询资讯。
- 检查服务不可用和空结果两种情况：前者应提示检查连接或稍后重试，后者应提示换词或调整时间窗。两者不要共用“没有新闻”提示。

参考实现：AIHOT 的 `apps/web/app/routes/agent.tsx` 负责页面与标签状态，`apps/web/app/features/agent/panels.tsx` 负责各方式的配置示例，`CodeBlock.tsx` 负责复制交互。可借鉴分工与信息顺序，具体框架和视觉组件沿用本站约定。
