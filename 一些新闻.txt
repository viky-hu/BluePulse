9月20日	湖北天门：筹建公安大模型智能运算体系	天门公安新一代“指挥超图平台”投入实战，并明确下一步专项部署算力服务器集群、搭建公安大模型智能运算体系，用于自动分析、智能研判和提前预警。	大模型 + 情指行 + 预测预警开始结合，模型不再只是办公问答，而是向指挥决策链路进入。

8月27日	宝鸡公安展示 AI 智能体实战应用	宝鸡公安科信建设现场会上集中展示 AI 智能体应用，并提出“警种主责、科信支撑、专班建模”，围绕高频警务场景研发模型。	一个重要趋势是：业务警种定义任务，技术部门提供 Agent / 模型开发能力，类似警务内部 AI 开发平台。
8月6日公开	公安部交通管理科学研究所采购大模型微调训练服务器	采购意向明确配置“大模型微调训练服务器”，要求至少 4 张单卡80GB显存 GPU，并支持国产操作系统。	公安科研机构正在形成自己的模型微调和私有化训练基础设施，说明需求不只是调用通用模型 API。
2026年	无锡：855.51万元建设警务大模型综合应用项目	项目包括智能体开发平台、知识库平台、警务语音引擎、知识问答、风险分析、数据分析研判、协同警务等，并采购训推一体服务器。	架构已经非常完整：LLM底座 → 知识库/RAG → Agent开发平台 → 警务场景应用，比较适合当作国内警务大模型技术架构样本研究。

其中我认为丽水的1838个警务AI助手最值得继续追踪。它意味着国内部分公安机关的大模型建设重点已经开始由“建设一个警务大模型”转向：

统一模型/算力底座 → 智能体开发平台 → 各警种自行构建 Agent → Agent 共享与复用。

这与你关注的 Agent 安全、工具调用和记忆安全其实也会产生直接交集。

美国还有一条非常明确的产品化路线：Axon 的 Draft One 已将生成式 AI 和执法记录仪结合，通过 BWC音频 → 自动转写 → LLM生成警情报告初稿 → 警员核验签字完成警务文书生成，并保留审计轨迹。2026年的版本进一步能够读取人员、车辆、财物等案件结构化字段，并根据证据主动向警员提出需要补充的问题。
